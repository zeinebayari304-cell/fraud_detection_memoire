1.3 Option A — avec Docker (recommandé, fonctionne sur toute machine)

  1. Installez Docker Desktop et démarrez-le.
  2. Copiez .env.example en .env et remplissez : POSTGRES_PASSWORD (lettres et chiffres), FRAUD_JWT_SECRET (longue chaîne aléatoire), et le premier administrateur FRAUD_ADMIN_USERNAME, FRAUD_ADMIN_EMAIL, FRAUD_ADMIN_PASSWORD.
  3. Lancez : 
    docker compose up -d --build
    La première construction prend quelques minutes.
  4. Ouvrez http://localhost:8080 et connectez-vous avec l'administrateur du .env.

La base PostgreSQL est conservée entre les redémarrages (volume pgdata). docker compose down arrête tout ; docker compose down -v supprime aussi la base.

1.4 Option B — sans Docker (développement, Windows)

  1. Installez Python 3.11+ (cochez « Add Python to PATH »), Node.js 20.19+ et VS Code.
  2. Dans VS Code, menu Terminal → Exécuter la tâche : Backend : installer les dépendances puis Frontend : installer les dépendances.
  3. Facultatif : créez .env (le premier administrateur et le secret de session y sont lus ; la base reste SQLite dans backend/data/app.db).

3. Comptes et rôles

Toutes les pages exigent une connexion (session JWT), comme l'indique le diagramme de cas d'utilisation. Le serveur vérifie le rôle à chaque requête.

RôleAccès
Analyste antifraudetableau de bord, analyse de transaction, analyse CSV, transactions (CRUD), historique et export
Expert cybersécurité / Data Scientisttableau de bord, comparaison des modèles, attaques ZOO / HopSkipJump, adversarial training, modèle final et tests en direct, historique
Administrateurutilisateurs et rôles, journal d'audit, et toutes les fonctions de l'analyste et de l'expert : un seul compte administrateur suffit pour tester toute l'application
  • Inscription : crée un compte « Analyste » ; l'administrateur peut changer le rôle.
  • Contrôle de saisie : nom d'utilisateur de 3 à 30 caractères commençant par une lettre ; e-mail valide ; mot de passe d'au moins 8 caractères avec majuscule, minuscule et chiffre, sans le nom d'utilisateur ; confirmation identique. Les erreurs s'affichent sous chaque champ.
  • Sécurité : mots de passe chiffrés (bcrypt) ; 5 échecs verrouillent le compte 15 minutes ; la déconnexion, la désactivation, le changement de rôle et la réinitialisation du mot de passe ferment les sessions ouvertes ; il reste toujours un administrateur actif.

7. Limites

  • Les modèles ont été évalués sur un seul jeu de données (cartes européennes, 2013).
  • Les chiffres de robustesse viennent de petits panels d'attaques : observations empiriques, pas des garanties.
  • Outil d'aide à la décision : une transaction signalée doit être vérifiée.
  • Les tables sont créées au démarrage (pas encore d'outil de migration).
